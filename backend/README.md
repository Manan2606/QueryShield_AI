# QueryShield AI Backend

FastAPI backend skeleton for QueryShield AI.

## Run Locally

Use the backend virtual environment commands below. Prefer `python -m uvicorn` and `python -m alembic` so PowerShell uses the active environment instead of a global Python install.

```bash
python3.11 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m uvicorn app.main:app --reload
```

On Windows:

```powershell
py -3.11 -m venv .venv
.venv\Scripts\activate
python -m pip install -r requirements.txt
python -m uvicorn app.main:app --reload
```

If `uvicorn app.main:app --reload` fails with a SQLAlchemy error from a Python 3.13 path, stop the server and rerun it with the activated Python 3.11 virtual environment command:

```powershell
python -m uvicorn app.main:app --reload
```

API docs are available at:

http://127.0.0.1:8000/docs

## Database Migrations

The initial migration already exists. Apply migrations with:

```bash
python -m alembic upgrade head
```

On Windows, from `backend/`:

```powershell
python -m alembic upgrade head
```

Create a new autogenerated migration only after future model changes:

```bash
python -m alembic revision --autogenerate -m "describe migration"
```

## Authentication (Step 3)

### Signup

Create a user account with:

```bash
curl -X POST http://127.0.0.1:8000/auth/signup \
  -H "Content-Type: application/json" \
  -d '{"email":"user@example.com","password":"password123","full_name":"Test User"}'
```

### Login

Log in with form data and receive a bearer token:

```bash
curl -X POST http://127.0.0.1:8000/auth/login \
  -H "Content-Type: application/x-www-form-urlencoded" \
  -d "username=user@example.com&password=password123"
```

### Protected route

Use the returned token to access your profile:

```bash
curl -X GET http://127.0.0.1:8000/users/me \
  -H "Authorization: Bearer <access_token>"
```

## Datasets (Step 4)

All dataset endpoints require a bearer token from the login flow.

### Create a dataset

```bash
curl -X POST http://127.0.0.1:8000/datasets \
  -H "Authorization: Bearer <access_token>" \
  -H "Content-Type: application/json" \
  -d '{"name":"Sales Data","description":"Monthly sales CSV dataset"}'
```

### List datasets

```bash
curl -X GET http://127.0.0.1:8000/datasets \
  -H "Authorization: Bearer <access_token>"
```

### Read one dataset

```bash
curl -X GET http://127.0.0.1:8000/datasets/1 \
  -H "Authorization: Bearer <access_token>"
```

### Update a dataset

```bash
curl -X PATCH http://127.0.0.1:8000/datasets/1 \
  -H "Authorization: Bearer <access_token>" \
  -H "Content-Type: application/json" \
  -d '{"name":"Updated Sales Data","status":"draft"}'
```

### Delete a dataset

```bash
curl -X DELETE http://127.0.0.1:8000/datasets/1 \
  -H "Authorization: Bearer <access_token>"
```

## CSV Uploads (Step 5)

Authenticated users can upload a CSV file for an existing dataset. The backend stores the file locally, infers simple column types, saves the detected schema, and returns a small preview of the data.

### Upload a CSV

```bash
curl -X POST http://127.0.0.1:8000/datasets/1/upload-csv \
  -H "Authorization: Bearer <access_token>" \
  -F "file=@/path/to/data.csv"
```

### Preview uploaded CSV rows

```bash
curl -X GET http://127.0.0.1:8000/datasets/1/preview \
  -H "Authorization: Bearer <access_token>"
```

## BigQuery Loading (Step 6)

Step 6 loads an already-uploaded CSV dataset from local storage into a BigQuery table. It does not add Gemini, SQL generation, SQL validation, cost estimation, arbitrary query execution, a frontend, or background workers.

### Google Cloud / BigQuery Setup

You need:

1. A Google Cloud project.
2. The BigQuery API enabled.
3. A BigQuery dataset ID configured in `.env`.
4. Application Default Credentials or a service account JSON.
5. IAM permissions that allow creating datasets/tables and running load jobs.

Minimum recommended IAM roles for local development:

- BigQuery Data Editor
- BigQuery Job User

Set these environment variables in `backend/.env`:

```bash
GCP_PROJECT_ID=your-gcp-project-id
BIGQUERY_DATASET_ID=queryshield_demo
GOOGLE_APPLICATION_CREDENTIALS=/absolute/path/to/service-account.json
```

Keep service account credentials outside this repository. Do not commit service account JSON files.

### Load CSV into BigQuery

`POST /datasets/{dataset_id}/load-bigquery`

Requires:

`Authorization: Bearer <access_token>`

```bash
curl -X POST "http://127.0.0.1:8000/datasets/1/load-bigquery" \
  -H "Authorization: Bearer <access_token>"
```

On success, the dataset status becomes `loaded` and `bigquery_table_id` is stored on the dataset record.

### Get BigQuery Table Info

`GET /datasets/{dataset_id}/bigquery-info`

Requires:

`Authorization: Bearer <access_token>`

```bash
curl -X GET "http://127.0.0.1:8000/datasets/1/bigquery-info" \
  -H "Authorization: Bearer <access_token>"
```
